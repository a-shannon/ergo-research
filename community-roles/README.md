# Contribute an N0 proof of the work tree or difficulty rules

Two people can work on the same Ergo history independently. Role 2 proves the work-tree relation. Role 4 proves the height and difficulty-adjustment relation. Each assignment returns a single 9,280-byte argument for the same statement, key and commitment. The assembler checks these inputs and the resulting claim against its own witness. The completed certificate also requires a common Dory opening, native proof-of-work checks and continuation checks.

Request one role in its [assignment issue](https://github.com/a-shannon/ergo-research/issues?q=is%3Aissue+N0+volunteer). Wait for a maintainer to confirm your name there before building the witness or starting the role. If you have to stop, tell the maintainer so someone else can take the assignment.

## Inputs and resources

| Item | Value |
| --- | --- |
| N0 mainnet history | 1,819,648 headers from genesis |
| Maturity height | 1,804,171 |
| Targeted build | 64-bit Windows, Python 3.12+, Rust with the MSVC linker and Windows SDK |
| Historical toolchain | Rust and Cargo 1.97.1 |
| Producer resources | Two Rayon workers. Allow 24 GiB free RAM for role production and extra memory for the OS. |
| Disk | A prepared packed witness takes 256 GiB. Reconstruction needs **at least 512 GiB free**, plus room for the extracted headers, build and temporary files. |
| Expected time | Building the witness can take days before the role starts. Times for roles 2 and 4 on this snapshot are still unknown. Plan for an uninterrupted role run. |

The public statement and Dory commitment are included in `public/`. This profile uses the diagnostic BN254/log41 key. The common opening is generated by the assembler after the seven claims are available.

## Get the witness

Download [the historical producer inputs](https://github.com/a-shannon/ergo-research/releases/download/nipopow-v2-community-roles-r1/ergo-nipopow-v2-aud2-historical-producer-inputs.zip) and verify its SHA-256, `9f4db1929fb3a0004f48c007536c97d0663d18f2cea6b9128c8aba64dbf1aa50`. Extract it into an empty directory. It contains the source and the 1,827,840 public headers used for both snapshots. The N0 generator selects its own prefix. From the extraction directory:

```powershell
$kit = (Resolve-Path ./era-bound-verifier-kit).Path
$headers = (Resolve-Path ./prefix-1827840.u32le).Path
$state = Join-Path (Get-Location).Path 'producer-work'
foreach ($stage in 'inputs','witness') {
    python -I -B ./producer/producer.py $stage N0 --kit $kit --work $state --headers $headers
    if ($LASTEXITCODE) { throw "N0 $stage failed" }
}
$witness = (Resolve-Path (Join-Path $state 'headers/N0/full.bits')).Path
```

To resume witness construction, use the same generator executable and work directory. If you already have the matching N0 `full.bits`, set `$witness` to its absolute path and skip the reconstruction. The role producer checks its BLAKE2b-512 digest before starting. The expected value is:

```text
de2057b4549f240160e811b7cf09c22e875b03916d6276b0de5998dabcf5f8f4644c7924c0245d621bb50fb16ac45e973a3a69b0ae5ed64e5251c05a5d0682ac
```

## Produce and return one argument

From the community kit directory containing `contribute.py`, set `$role` to your assigned number. Keep this source directory in place after building. Choose an output directory that does not exist yet, outside both the kit and the witness directory.

```powershell
$role = 2  # use 4 for height and difficulty
$work = Join-Path (Split-Path (Get-Location).Path) 'community-build'
$out = Join-Path (Split-Path (Get-Location).Path) "n0-role-$role-output"
python -I -B ./contribute.py produce --role $role --work $work --witness $witness --out $out
if ($LASTEXITCODE) { throw 'Role production or public verification failed' }
Get-FileHash -Algorithm SHA256 (Join-Path $out "role-$role.gkr")
```

The producer writes its proof to disk and the launcher invokes a separate verifier. The verifier derives an evaluation claim from the bytes. The running N0 producer uses an earlier build. A compatible assembler can admit a returned argument when it starts a new run. It checks the argument independently and reads its own 256 GiB witness once per contributed role to check the claim. A complete N0 certificate still needs the common opening, native proof-of-work audit and continuation checks.

Return the standalone `role-2.gkr` or `role-4.gkr` via a **commit permalink in your public fork**, with its SHA-256 and byte length in the assignment issue. If you measured elapsed time and know your CPU model, include those as well. The proof bytes are the entire contribution. The receiver uses the statement, key and commitment already in its own kit.

To check a returned role file yourself:

```powershell
python -I -B ./contribute.py verify --role $role --work $work --proof (Join-Path $out "role-$role.gkr")
```

In the 3,073-header demonstration, the assembler accepted two arguments produced by separate processes and recomputed the common opening. The larger N0 profile still awaits this end-to-end check.
