# NiPoPoW V2 progress checkpoint

*4 November 2026*

This research prototype aims to let a resource-constrained Ergo client check a compact claim about canonical header history from genesis to a recent tip. The intended path covers legacy RAW headers and all difficulty adjustment eras, exact work and tree commitments, sampled Autolykos v1 and v2 checks, origin handling, chain comparison and continuation. A complete genesis-to-tip run has not been demonstrated.

The 22–28 October update described an exported packet verified by a cold consumer in a synthetic large-domain experiment. This checkpoint adds a real historical-data join. The new joint test produces and verifies proofs within one process; it does not extend the earlier cold-consumer result to a complete historical proof.

## Real historical-data join

The joint case passed on the first three retained mainnet RAW headers, four physical owners and the retained test key at log_n = 22. It generated and verified POINT GKR plus its PCS opening, then generated and verified HEADER against the same original witness X and cryptographic commitment C. Encoded verification, altered proofs and openings, wrong commitments and coherent alternative parents were checked, including unchanged transcript continuations on rejection. The HEADER alias-row check detects detached serializer bytes that POINT membership alone does not constrain.

The complete test passed with zero failures and its actual result record was independently reviewed. Its 524,288-byte packed input is retained in matching read-only copies. Proof objects and encoded proof buffers stayed in memory; this run exported no proof packet. An earlier three-header HEADER-only result covers a separate case. The full historical certificate still needs the remaining mandatory roles and their shared-commitment composition.

The native PCS source remains at N3/H2. Key-41 consumer geometry still leaves a producer gap: current sparse producer admission rejects H21 before opening the source or performing setup or commitment.

## Security and resource limits

The prototype uses GKR-Dory over BN254 with a retained experimental key. A production curve, key, setup, extraction model and concrete security budget have not been adopted. The design target has no hard fork, EIP-0045, external oracle or trusted third party. Its security argument remains incomplete, so no production security guarantee follows.

Full S, all producer roles, global soundness and honest completeness, chain comparison and continuation, package and reproduction instructions, the revised paper and PDF, and verified delivery remain open. The client target is four CPU cores, 8 GiB RAM and no GPU. No full-history client measurement supports that budget yet. This note contains no prototype source, so its local results cannot be replayed from this repository.
